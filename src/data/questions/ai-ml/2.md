## Question
In a transformer, explain what the attention mechanism computes and why queries, keys, and values are separate learned projections rather than using the input directly.

## Hint
Think of it as a soft, differentiable lookup: for each position, "how relevant is every other position's content to me, and what should I take from it?"

## Answer
Attention computes a weighted sum of "value" vectors, where the weights come from a compatibility score between a "query" (from the current position) and "keys" (from every position), normalized via softmax. Separate Q/K/V projections let the model learn distinct roles for "what am I looking for," "what do I offer to be matched against," and "what do I actually contribute," rather than being forced to reuse the same representation for all three.

## Solution
For each position, its query vector $q$ is compared against every position's key vector $k_i$ via a dot product, scaled by $1/\sqrt{d_k}$ (to keep gradients well-behaved as dimensionality grows), then softmaxed into attention weights $\alpha_i$. The output is $\sum_i \alpha_i v_i$, a weighted blend of every position's value vector.

Using the raw input embedding for all three roles would force one vector to simultaneously encode "what this token is looking for," "how this token should be found by others," and "what this token contributes when found" -- three different jobs that don't need to share a representation. Learning separate $W_Q, W_K, W_V$ projection matrices lets the model specialize: a verb's query might learn to look for its subject, its key might make it easy for a nearby pronoun to find, and its value carries the semantic content actually passed forward -- three different vectors derived from the same input, each optimized for its own role in the mechanism.
