## Question
State the four necessary conditions for a deadlock to occur between processes competing for resources, and explain why removing any one of them prevents deadlock.

## Hint
Think about what has to be simultaneously true right before a set of processes gets stuck waiting on each other in a cycle.

## Answer
Mutual exclusion, hold-and-wait, no preemption, and circular wait -- all four must hold simultaneously.

## Solution
- **Mutual exclusion**: at least one resource is held in a non-shareable mode (only one process can use it at a time).
- **Hold and wait**: a process holds at least one resource while waiting to acquire additional resources held by others.
- **No preemption**: a resource can only be released voluntarily by the process holding it, never forcibly taken away.
- **Circular wait**: there's a cycle of processes P1, P2, ..., Pn where each Pi is waiting on a resource held by P(i+1 mod n).

Breaking any single one prevents deadlock, which is exactly how the standard prevention strategies work: allowing resource sharing where possible removes mutual exclusion; requiring processes to request all resources upfront (or release held ones before requesting more) removes hold-and-wait; allowing forced preemption removes no-preemption; and imposing a global ordering on resource acquisition removes circular wait (a cycle is impossible if every process only ever requests resources "later" in a fixed order).
