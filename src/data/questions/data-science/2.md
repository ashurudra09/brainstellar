## Question
A dataframe column has 15% missing values. What are your options for handling it, and how would you decide between them?

## Hint
The right answer depends heavily on *why* the data is missing (missing completely at random vs. missing for a reason tied to the value itself) and on how the column will be used downstream.

## Answer
Drop, impute (mean/median/mode, or model-based), or add a "missingness" indicator flag -- the choice depends on the missingness mechanism and how much of the column (and how many rows overall) would be lost.

## Solution
- **Drop rows/columns**: reasonable when missingness is a small fraction of a large dataset and appears random (MCAR) -- but at 15% you risk losing real signal, and dropping is never appropriate if missingness correlates with the outcome you're modeling (that's exactly the information the model would need).
- **Simple imputation** (mean/median for numeric, mode for categorical): quick and fine for tree-based models or as a baseline, but it artificially shrinks variance and can bias downstream statistics if missingness isn't random.
- **Model-based imputation** (e.g. KNN or regression imputation): more accurate when other columns predict the missing one well, at the cost of complexity and the risk of leaking test-set information if not fit only on training data.
- **Missingness indicator**: add a binary "was this missing" column alongside an imputed value. This is often the safest default when missingness itself might be predictive (e.g. a customer skipping the "income" field on a form) -- it lets the model use that signal directly instead of hiding it behind an imputed number.

In practice: first check *why* the values are missing (look for a pattern against other columns/labels), then default to imputation + an indicator flag unless there's a clear reason to drop.
