## Question

Let $G$ be an unweighted graph (directed or undirected) and let BFS run from
a source node $s$, assigning each node $u$ a label $\text{dist}[u]$ equal to
the number of edges on the path used to first discover it (i.e.
$\text{dist}[u] = \text{dist}[p] + 1$ where $p$ is the node that pushed $u$
onto the queue, and $\text{dist}[s] = 0$).

**Prove formally** that when BFS dequeues a node $u$, $\text{dist}[u]$
equals $\delta(s, u)$, the true shortest-path distance from $s$ to $u$ in
$G$.

## Hint

Prove this as an invariant on the queue first: at any point during BFS, the
queue contains nodes from at most two distinct distance labels, $d$ and
$d+1$, and all the $d$-labeled nodes appear before all the $d+1$-labeled
nodes. Use induction on the sequence of dequeue operations to establish
this. Then use the invariant to drive a proof by contradiction (smallest
counterexample) for the main claim.

## Solution

**Step 1 — Queue invariant.** At any point during BFS, the queue's
contents have labels from at most two consecutive values $d$ and $d+1$,
appearing in non-decreasing order.

*Base case:* the queue starts as $[s]$ with label $0$ — trivially one
distinct value.

*Inductive step:* assume the queue currently looks like
$[\underbrace{d,\dots,d}_{}, \underbrace{d+1,\dots,d+1}_{}]$. Dequeue the
front element:

- If it has label $d$, its unvisited neighbors are labeled $d+1$ and
  appended to the back. The queue still has a block of $d$'s (one shorter)
  followed by a block of $d+1$'s. Invariant preserved.
- If the $d$-block is already empty, the front element has label $d+1$; its
  neighbors are labeled $d+2$ and appended. The queue's shape shifts up by
  one but keeps exactly two consecutive labels. Invariant preserved.

This works because BFS pushes to the back and pops from the front (FIFO),
and every node's label is exactly one more than the label of the node that
discovered it — so labels can never be pushed out of non-decreasing order.

**Step 2 — Main claim, by contradiction (smallest counterexample).**
Suppose some node's BFS label is wrong. Let $v$ be the node with the
*smallest* true distance $\delta(s,v)$ among all such counterexamples, and
say $\text{dist}[v] = d \ne \delta(s,v)$.

Let $p$ be $v$'s predecessor on a true shortest path, so
$\delta(s,p) = \delta(s,v) - 1$. Since $p$'s true distance is strictly
smaller than $v$'s, and $v$ was chosen as the smallest counterexample, $p$
must be labeled correctly: $\text{dist}[p] = \delta(s,p)$.

When $p$ is dequeued, BFS examines all of $p$'s neighbors, including $v$
(since the edge $p \to v$ exists):

- If $v$ is not yet visited, it is labeled $\text{dist}[p] + 1 =
  \delta(s,v)$ right then — contradicting $v$ being mislabeled.
- If $v$ was already visited before $p$ was dequeued, then by the queue
  invariant (Step 1) every node discovered so far has label
  $\le \text{dist}[p] + 1 = \delta(s,v)$, since $p$ has not yet been
  dequeued and the queue's labels are non-decreasing. So
  $\text{dist}[v] \le \delta(s,v)$. But also $\text{dist}[v] \ge
  \delta(s,v)$ always, since every BFS label corresponds to the length of
  an actual walk from $s$ to that node, and no walk can be shorter than the
  true shortest path. Combining both bounds, $\text{dist}[v] =
  \delta(s,v)$ — again a contradiction.

Either way $v$ cannot be a counterexample, so no counterexample exists.
$\blacksquare$

**The two load-bearing facts:** (1) the queue's labels are non-decreasing
(Step 1), and (2) every label BFS assigns corresponds to a real walk, so it
can never undershoot the true distance — it can only be confirmed or shown
to already match via the smallest-counterexample argument.

### Follow-up: what changes for directed or weighted graphs?

- **Directed graphs:** the proof is unchanged. Nothing in Step 1 or Step 2
  used symmetry of edges — "neighbor" throughout just means "edge leaving
  the current node," which is exactly as well-defined directed as
  undirected. The only place direction matters at all is which nodes are
  reachable from $s$ in the first place.
- **Weighted graphs:** the proof breaks specifically where Step 1's
  invariant is built — "neighbors get label exactly one more than their
  discoverer" relies on every edge costing exactly $1$. With arbitrary
  weights, a node reached via a heavy edge could get a much larger label
  than a node reached later via a light edge, so the queue is no longer
  sorted by label and the two-consecutive-labels invariant collapses
  entirely. This is precisely the gap Dijkstra's algorithm closes: replace
  the FIFO queue with a **min-heap keyed on tentative distance**, so you
  always expand the globally smallest unfinalized label next. The
  correctness proof for Dijkstra (Module 4) reuses this same
  smallest-counterexample skeleton, with non-negative edge weights doing
  the job that "all edges cost 1" did here — the step "$\delta(s,y) \le
  \delta(s,u)$" in that proof is exactly where non-negativity is spent.
