## Question
You are given a tree $T$ with $N \le 10^5$ vertices. Each vertex is independently coloured black or white, each with probability $1/2$. Let $G$ be the smallest connected subgraph of $T$ that contains every black vertex (so $G$ consists of all the black vertices, plus whatever white vertices are needed to keep them all connected — this is sometimes called the Steiner tree of the black vertices within $T$).

Find the expected number of white vertices in $G$.

## Hint
Never try to describe $G$ as a whole — use linearity of expectation and indicators instead: $E[\#\text{white in } G] = \sum_v P(v \text{ is white and } v \in G)$. For a fixed white vertex $v$, think about what happens to the tree when you delete $v$: it splits into several pieces (one per neighbor of $v$). When is $v$ actually needed to hold the black vertices together?

## Answer
$$E[\#\text{white in } G] = \sum_{v \in T} \frac{1}{2}\left(1 - 2^{-(N-1)} - \sum_{j} \left(1 - 2^{-s_j(v)}\right)2^{-(N-1-s_j(v))}\right)$$
where $s_1(v), \ldots, s_k(v)$ are the sizes of the components formed by deleting $v$ from $T$. Computable in $O(N)$ total via one DFS.

## Solution

### Step 1: Don't describe $G$ directly — use linearity of expectation

$G$ is a complicated, randomly-shaped object — trying to reason about its size or structure as a whole is a dead end. The standard rescue for "expected size of some structurally-defined set" is **linearity of expectation via indicators**: write

$$\#\text{white in } G = \sum_{v \in T} \mathbb{1}[v \text{ is white}] \cdot \mathbb{1}[v \in G]$$

Taking expectations (linearity holds regardless of how dependent these indicators are on each other):

$$E[\#\text{white in } G] = \sum_{v \in T} P(v \text{ is white and } v \in G) = \sum_{v \in T} P(v \text{ is white}) \cdot P(v \in G \mid v \text{ is white})$$

$$= \sum_{v \in T} \frac{1}{2} \cdot P(v \in G \mid v \text{ white})$$

So the whole problem reduces to computing, for **one fixed vertex $v$** at a time, the single number $P(v \in G \mid v \text{ is white})$.

### Step 2: When is a white vertex $v$ forced into $G$?

Picture deleting $v$ from the tree $T$. Since $T$ is a tree, removing any single vertex splits the rest into several disconnected pieces — exactly one piece per neighbor of $v$. If $v$ has degree $k$, call the resulting component sizes $s_1, s_2, \ldots, s_k$ (these satisfy $s_1 + \cdots + s_k = N - 1$, since together the components contain every vertex except $v$ itself).

Because $v$ is the only vertex connecting these pieces back together, a black vertex sitting in piece $i$ can only reach a black vertex sitting in a *different* piece $j$ by passing back through $v$. So:

**$v$ (white) is forced into $G$ if and only if at least two of the $k$ pieces each contain at least one black vertex.** If zero pieces contain a black vertex, or exactly one piece does, then $v$ is not acting as a connector for anyone, and the minimal spanning subgraph can skip it entirely.

### Step 3: Compute $P(v \in G \mid v \text{ white})$ via the complement

"At least two pieces have a black vertex" is annoying to compute directly (it has many sub-cases: exactly 2, exactly 3, ..., exactly $k$ pieces). Its complement is much simpler, since it only has **two** mutually exclusive cases:

$$P(v \notin G \mid v \text{ white}) = P(\text{0 pieces have black}) + P(\text{exactly 1 piece has black})$$

**Case 1: zero pieces have a black vertex.** This means every one of the $N-1$ non-$v$ vertices is white. Since each is independently white with probability $1/2$:

$$P(\text{0 pieces have black}) = \left(\frac{1}{2}\right)^{N-1}$$

**Case 2: exactly one piece has a black vertex** (and every other piece is entirely white). Sum this over which piece $j$ is the one that has the black vertex:

- $P(\text{piece } j \text{ has at least one black vertex}) = 1 - \left(\frac{1}{2}\right)^{s_j}$ (complement of "piece $j$ entirely white")
- $P(\text{every other piece entirely white}) = \left(\frac{1}{2}\right)^{(N-1) - s_j}$ (there are $(N-1) - s_j$ vertices outside piece $j$)

So:

$$P(\text{exactly 1 piece has black}) = \sum_{j=1}^{k} \left(1 - \left(\frac{1}{2}\right)^{s_j}\right) \left(\frac{1}{2}\right)^{(N-1)-s_j}$$

**Putting it together:**

$$P(v \in G \mid v \text{ white}) = 1 - 2^{-(N-1)} - \sum_{j=1}^{k} \left(1 - 2^{-s_j}\right) 2^{-(N-1-s_j)}$$

### Step 4: Assemble the final answer

$$E[\#\text{white in } G] = \sum_{v \in T} \frac{1}{2}\left(1 - 2^{-(N-1)} - \sum_{j} \left(1 - 2^{-s_j(v)}\right)2^{-(N-1-s_j(v))}\right)$$

### Step 5: Computing this in $O(N)$ — the implementation

The only nontrivial part left is: for *every* vertex $v$, get the sizes of the components formed by deleting $v$. A single DFS/BFS gives you this for the whole tree at once.

**Pseudocode:**

```
# Root the tree arbitrarily, say at vertex 1.
# subtree_size[v] = number of vertices in v's subtree (including v),
# computed with a standard post-order DFS.

function compute_subtree_sizes(root):
    subtree_size = array of size N, initialized to 1
    order = []  # post-order (children fully processed before parent)
    stack = [(root, None, False)]
    while stack not empty:
        (node, parent, processed) = stack.pop()
        if processed:
            for child in children[node]:
                subtree_size[node] += subtree_size[child]
            order.append(node)
        else:
            stack.push((node, parent, True))
            for child in neighbors[node] if child != parent:
                stack.push((child, node, False))
    return subtree_size

# For a vertex v with parent p and children c1, c2, ..., cm (in the rooted tree),
# deleting v from the ORIGINAL (unrooted) tree produces exactly these components:
#   - one component per child c_i, of size subtree_size[c_i]
#   - one "upward" component containing everything NOT in v's subtree,
#     of size N - subtree_size[v]  (this piece is absent / size 0 if v is the root)

function component_sizes_after_deleting(v, subtree_size, N):
    sizes = []
    for child in children[v]:
        sizes.append(subtree_size[child])
    if v is not root:
        sizes.append(N - subtree_size[v])
    return sizes   # these are exactly s_1, ..., s_k for vertex v

function solve(tree, N):
    subtree_size = compute_subtree_sizes(root = 1)
    total_expectation = 0.0
    inv2 = 1.0 / 2
    for v in 1..N:
        sizes = component_sizes_after_deleting(v, subtree_size, N)
        p_zero = inv2 ** (N - 1)
        p_exactly_one = 0.0
        for s in sizes:
            p_exactly_one += (1 - inv2 ** s) * (inv2 ** (N - 1 - s))
        p_v_in_G_given_white = 1 - p_zero - p_exactly_one
        total_expectation += 0.5 * p_v_in_G_given_white
    return total_expectation
```

**Why this is $O(N)$ overall:** `compute_subtree_sizes` is one linear-time DFS. The outer loop over vertices visits each vertex once, and for each vertex $v$, the inner loop over `component_sizes_after_deleting(v, ...)` costs time proportional to $v$'s degree (one entry per child, plus possibly one "upward" entry) — summed over all vertices, the total work across all these inner loops is $O(N)$, since the sum of all vertex degrees in a tree is exactly $2(N-1)$ (handshake lemma). The powers of $1/2$ can be precomputed once (or computed via fast exponentiation / cached logarithms) to avoid repeated expensive exponentiation, keeping the whole algorithm at $O(N)$.

### Reflex to keep

**Never try to describe a randomly-defined structural object (here, the Steiner tree $G$) directly.** Instead, decompose the quantity you actually want (its size) into a sum of indicators over the individual pieces (vertices), and compute each indicator's probability in isolation — this is exactly the same move as the "expected number of correct envelopes" or "expected number of adjacent HH pairs" drills, just with a membership condition that requires understanding the tree's local branching structure instead of a simple coin flip. When the direct probability of an event ("at least two things happen") is annoying to compute, flip to its complement whenever the complement only has a small, enumerable number of cases — here, "0 or 1 pieces have black" collapses a many-case sum into just two clean terms.
