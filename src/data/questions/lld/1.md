## Question
Design the classes for a multi-level parking lot that supports motorcycles, cars, and buses (a bus needs 5 contiguous compact-or-larger spots), tracks availability per level, and computes a parking fee on exit.

## Requirements
- Multiple levels, each with a fixed count of spots per size class (motorcycle/compact/large).
- Assign the smallest spot that fits a vehicle; a bus needs 5 contiguous large spots on one level.
- Fee is a function of vehicle type and duration.
- Must answer "is the lot full?" in O(1).

## Hint
Model spot allocation as a strategy the lot delegates to, per vehicle type, rather than a chain of `if vehicle is Bus` checks in one God method.

## Approach
- `ParkingSpot` (abstract) with `Motorcycle/Compact/Large` subclasses holding a size enum and occupancy flag.
- `Level` owns a list of spots and a free-count per size, updated on park/leave for O(1) fullness checks.
- `ParkingLot` owns levels and a `Vehicle -> SpotAllocationStrategy` map (Strategy pattern) so adding a new vehicle type doesn't touch existing allocation code.
- `Ticket` records vehicle, spot(s), and entry time; fee computed from `Ticket` + a `FeePolicy` (Strategy pattern again) on exit.

## Trade-offs
Strategy objects add a layer of indirection for what could be a couple of `if` statements at this scale -- worth it here because vehicle-specific allocation rules (a bus needing 5 *contiguous* spots) are exactly the kind of rule that grows special cases over time; not worth it if the lot only ever handles one vehicle type.

## Code
```python
class SpotAllocationStrategy:
    def allocate(self, level, vehicle): ...

class BusAllocationStrategy(SpotAllocationStrategy):
    def allocate(self, level, vehicle):
        return level.find_contiguous_large(count=5)

class ParkingLot:
    def __init__(self, levels, strategies):
        self.levels = levels
        self.strategies = strategies  # {VehicleType: SpotAllocationStrategy}

    def park(self, vehicle):
        strategy = self.strategies[vehicle.type]
        for level in self.levels:
            spots = strategy.allocate(level, vehicle)
            if spots:
                return level.occupy(spots, vehicle)
        return None  # lot full for this vehicle type
```

## Solution
The key design decision is keeping spot-allocation *rules* (what counts as a valid assignment for a vehicle) separate from spot-allocation *bookkeeping* (which spots are actually free right now, tracked per `Level`). That separation is what lets a bus's "5 contiguous large spots" rule live in its own strategy class instead of leaking into `Level` or `ParkingLot`, and it's the same reason the fee calculation is pulled out into its own policy object rather than a method on `Ticket` -- both are places the requirements are likely to grow (new vehicle types, new pricing tiers) without changing how spots are tracked.
